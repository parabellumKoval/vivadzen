## 1. ЧЕСТНЫЕ ОТВЕТЫ НА ВАШИ ВОПРОСЫ

### 1.1. Claude Design (Artifacts) или Claude Code?

Это разные инструменты для разных стадий. Для Vivadzen нужны оба, но в правильном порядке.

**Claude Artifacts (на claude.ai)** — это то, что у нас сейчас под рукой. Подходит для:
- прототипа **одного** экрана/компонента в React + Tailwind или чистом HTML/CSS
- визуальной проверки и итерации «как это будет выглядеть»
- быстрых демонстраций заказчику/команде

Ограничения: один артефакт ≈ один файл; нельзя build production e-shop с роутингом, корзиной с persistance, личным кабинетом, реальной интеграцией оплаты, age-gate как в проде. Это инструмент **дизайна**, не реализации.

**Claude Code** — CLI-инструмент для разработчиков. Подходит для:
- реальной сборки production-кодовой базы (Next.js / Astro / SvelteKit + БД + API)
- многофайловой структуры, миграций, тестов
- интеграции с платежами, GoPay/ComGate, age-gate, GBP, аналитикой

Ограничение: не заменяет фронтенд-разработчика, но сильно ускоряет его.

**Рекомендация по Vivadzen (честно):**
1. **Этап 1 — дизайн (Artifacts):** в этом чате/нескольких чатах прототипируем ключевые экраны (главная, категория, товар, чекаут) — фиксируем визуальный язык в React + Tailwind. Это станет визуальной ссылкой и одновременно «компонент-стартером» в коде.
2. **Этап 2 — реализация (Claude Code или разработчик с Claude Code):** на основе одобренных прототипов поднимается реальная кодовая база. Сюда же подключается ваш бэкенд (товары, заказы, кабинет, COA, лиды placeholder).

Полностью заменить разработчика одним Claude — пока нерабочая идея для реального PML-eshop с лицензированием, чекаутом и т.д. Это не «фальш», это просто текущее состояние инструментов.

### 1.2. Порционно или всё сразу скармливать ТЗ?

**Порционно.** Длинный контекст у любой LLM (включая Claude) деградирует — модель теряет детали. Правильный режим:

1. **Один раз скормить дизайн-систему** (файл 1 этого ТЗ) — она «настраивает» стиль.
2. **Дальше — один экран = одна сессия/один артефакт.** «Сделай главную по этому ТЗ» → итерации → следующий чат «сделай страницу товара по этому ТЗ» → итерации.
3. Между сессиями — переиспользовать «дизайн-токен файл» (компактная версия системы, см. файл 1 §11).

Скормить весь комплект из 7 файлов одной кнопкой можно — но Claude будет хуже фокусироваться, ответ станет общим и поверхностным. Лучший результат — фокусные сессии.

### 1.3. Векторные изображения через Nano Banana — возможно?

**Короткий ответ: для иконок и UI — нет, для иллюстраций — частично, для фотографий — отлично (но это растр).**

Что важно знать про Nano Banana (Gemini Image-модели):
- **Nano Banana** (Gemini 2.5 Flash Image) — раст. PNG 1024px, $0.039/изображение.
- **Nano Banana 2** (Gemini 3.1 Flash Image, февраль 2026) — лучше качество, баланс цена/скорость.
- **Nano Banana Pro** (Gemini 3 Pro Image) — лучшее качество, до 4K, «Thinking»-режим для сложных промптов, рендерит текст в картинке.
- **Все три выдают РАСТР (PNG)**, не SVG. Это нативно растровые модели.

Откуда брать векторы:
- **Иконки UI (корзина, плюс/минус, фильтры и т.п.)** → библиотека Lucide React (встроена в Claude Artifacts) или Heroicons. Готовые, бесплатные, оптимизированные SVG. **Не генерируйте — берите готовые.**
- **Логотип Vivadzen** → один раз нарисовать у дизайнера/в Figma → экспорт SVG. Это бренд-актив, не AI.
- **Декоративные иллюстрации (листья, узоры, паттерны)** → SVG можно попросить **Claude** сгенерировать прямо в чате (Claude хорошо умеет в SVG-код). Альтернатива: Gemini Pro тоже умеет в SVG-код (не в растр-картинку, а в код).
- **Иконки категорий / декоративные «глифы»** (как лист кратома, гриб, кофейное зерно из ваших скриншотов) → если нужны в стиле «3D tactile» (как на скриншоте 3) → Nano Banana **может это сделать как PNG** с прозрачным фоном через промпт; для масштабируемого вектора лучше нарисовать вручную или векторизовать через VectoSolve/Vector Magic после генерации.

**Итог по векторам для вас:**
- UI-иконки — Lucide (бесплатно, не генерируем).
- Логотип — SVG от дизайнера/Figma (один раз).
- Иллюстрации/паттерны — Claude генерирует SVG напрямую (в этом чате).
- Категорийные «глифы» в стиле скриншота 3 — Nano Banana PNG с прозрачным фоном (см. файл 5).

### 1.4. Нужно ли обрезать фон с фото?

Зависит от типа:

| Тип изображения | Фон | Как делать |
|---|---|---|
| Hero/lifestyle (баннеры) | оставить (это и есть атмосфера) | Nano Banana → PNG в нужном aspect ratio |
| Категорийные глифы (как скриншот 3) | прозрачный | Nano Banana с промптом «on transparent/pure white background» или удалить фон после |
| Карточка товара | белый или прозрачный | **Реальное фото вашего товара** на белом, потом remove.bg / Photoshop / Nano Banana edit |
| Логотипы платёжных систем | прозрачный | Скачать **официальные** SVG/PNG с пресс-кита (Visa/MC/Apple/Google имеют пресс-страницы) — НЕ генерировать AI |
| Лого транспортных/курьер | прозрачный | официальные пресс-материалы |

**Удаление фона — инструменты:**
- `remove.bg` (бесплатно для нескольких в день, $9.99/мес для API) — быстрее и чище всего.
- Nano Banana edit-режим (промпт «remove background, isolate subject on transparent») — работает, но не всегда чисто на сложных краях (волосы/трава).
- Photoshop / Photopea (бесплатный web-аналог) — для ручной финальной подчистки.
- Adobe Express / Canva (если у вас уже есть подписка) — встроено.

## 2. КЛЮЧЕВЫЕ НАБЛЮДЕНИЯ ПО ВАШЕМУ БРИФУ

### 2.1. Скриншоты-вдохновение vs реальная ассортиментная политика

В присланных скриншотах Vivadzen показан как «wellness-бренд» с категориями **Kratom + Cannabis + Mushrooms + Teas + Coffee + Entheogens + Superfoods**. Это сильный визуальный язык, но юридически по нашему первому ТЗ (SEO) **Vivadzen — специализированный PML-эshop по кратому** (так требует закон č. 167/1998 Sb. для PML-лицензии: «e-shop musí být výhradně specializovaný»).

**Развилка:**
- Если ассортимент **только кратом** → берём из скриншотов **только визуальный язык** (палитра, типографика, тон), а категории/CTA адаптируем под кратом.
- Если планируется расширение в сторону CBD/конопля/грибы → это **отдельные регуляторные режимы** (CBD ≠ PML, псилоцибиновые грибы → отдельная история), и фактически нужен второй бренд/сайт или мультибрендовая модель.

**Я делаю дизайн-ТЗ исходя из варианта «кратом-only с возможностью добавить связанные легальные категории (например чаи без PML) в будущем»**, но с защищённой архитектурой: «Kratom» — главная и единственная пока категория PML, остальные слоты структуры готовы под расширение, если/когда юридически прояснится. Если этот выбор неверный — скажите, я переделаю.

### 2.2. Обязательный регуляторный текст (важное уточнение)

В вашем брифе указан большой блок «Důležité bezpečnostní a spotřebitelské informace» с упоминанием эффектов («povzbuzující/tlumivé účinky», «může ovlivnit bdělost…») и návod k použití (3 g на дозу, max 10 g/день).

Это **обязательный регуляторный текст** по §33e zák. č. 167/1998 Sb. — он МЕНЯЕТ моё прежнее правило из SEO-ТЗ. Уточняю:

- ✅ **Этот текст идёт verbatim на каждую страницу товара** в выделенный регуляторный блок (см. файл 2, компонент `LegalSafetyBlock`).
- ✅ **Návod k použití с дозами 3 g / 10 g** — тоже в обязательный блок (это инструкция к продукту по требованию закона).
- ❌ **В рекламном/SEO-копирайте на главной, в категориях, в текстах гайдов — без эффект-промисов** (это и было моё прежнее правило, оно осталось).

То есть: **на товарной карточке** — обязательная регуляторная инструкция (включая эффекты как нейтральный факт + предупреждения + дозы). **В маркетинговых текстах** — без эффект-обещаний. Это разные функциональные слои контента, и закон их разделяет.

### 2.3. Что добавилось в функционал (фиксирую)

Сверх первого SEO-брифа появилось:
- **Подписка** на кратом → отдельная сущность товара, отдельная страница `/predplatne`, блок на товаре «Купить разово / Купить по подписке -10%».
- **Доставка messenger:** стандартная + **express ~180 мин** по Праге и Остраве (доплата). Это влияет на: шапку (баннер «Express dnes»), карточку товара, чекаут, страницу `/doprava-a-platba`.
- **Платежи:** + Apple Pay, Google Pay, Visa/Mastercard логотипы.
- **Trust-сообщения** про безопасный платёж / гарантия возврата / безопасность данных — в чекауте и в футере.
- **Google reviews** + общая оценка (виджет) + **внутренние** отзывы/вопросы под товаром + фотоотзывы → 3 источника в трёх местах (см. файл 2, компоненты).
- **Поэтапный чекаут** + личный кабинет + гостевой заказ + сохранённые способы доставки/оплаты.
- **Мини-карточка товара** с переключателем 25/50 г, цветовым кружком вены, штаммом, мита/помолом.
- **COA-блок** с конкретной таблицей значений + Stáhnout COA (PDF).
- **Страница поддержки** для вопросов/проблем.
- **Footer с лого AKREDITOVANÁ LABORATOŘ (VŠCHT Praha, ISO 17025) и AUTORIZOVANÝ PRODEJCE PML.**

Всё это разложено по компонентам и страницам в файлах 2–3.

### 2.4. Палитра, шрифты — приняты

Цвета:
- `#1B3A2D` — глубокий зелёный (primary surface / dark bg)
- `#F5EDD8` — кремовый бежевый (light surface)
- `#F9F4EC` — почти-белый кремовый (lightest / text on dark)
- `#7EC855` — травяной зелёный (accent / brand secondary)
- `#F4A020` — янтарный (primary CTA / orange highlight)
- `#D45C2B` — терракотовый (secondary CTA / sale / urgency)

Шрифты:
- **Playfair Display** (Italic, Bold) — заголовки, премиальный/heritage тон
- **Inter** (Regular, Medium, SemiBold, Bold) — body, UI, метрики
