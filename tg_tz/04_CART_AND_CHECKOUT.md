# 04 — Корзина, модификации и оформление заказа

## Корзина — состояние (Pinia)

**Файл:** `stores/cart.ts`

Использовать ту же логику и типы что в `src/front`.  
Добавить `localStorage` персистентность через `@pinia/plugin-persistedstate` если это уже есть в `src/front`.

```ts
interface CartItem {
  productId: string | number
  variantId?: string | number   // null если нет модификаций
  quantity: number
  // snapshot данных для отображения:
  name: string
  image: string
  price: number
  originalPrice?: number
  variantLabel?: string         // например "7g"
}

interface CartStore {
  items: CartItem[]
  // getters:
  totalQty: number
  totalPrice: number
  // actions:
  addItem(product, variant?): void
  removeItem(productId, variantId?): void
  updateQty(productId, variantId?, qty): void
  clear(): void
}
```

## UX-поток: Добавление в корзину

### Товар без модификаций

```
Пользователь нажимает [+ Добавить] на карточке
        ↓
cart.addItem(product)
        ↓
Кнопка трансформируется в счётчик [− 1 +]
        ↓
Бейдж на иконке корзины в BottomNav обновляется
```

### Товар с модификациями

```
Пользователь нажимает [+ Добавить] на карточке
        ↓
Открывается TgVariantSheet (bottom sheet)
        ↓
Пользователь выбирает вариант из чипов
        ↓
Нажимает [Добавить в корзину]
        ↓
cart.addItem(product, selectedVariant)
        ↓
Sheet закрывается
        ↓
Бейдж корзины обновляется
```

### На странице товара с модификациями

```
Переключатель вариантов сразу виден на странице
        ↓
Пользователь выбирает вариант
        ↓
Цена обновляется под выбранный вариант
        ↓
Кнопка [Добавить в корзину] активна
        ↓
После добавления — кнопка становится счётчиком
```

## Мини-корзина (Cart Preview)

Корзина не вынесена на отдельную страницу.  
Вместо этого — Bottom Sheet, открывающийся при нажатии на иконку корзины в BottomNav.

**Файл:** `components/cart/TgCartSheet.vue`

Структура:
```
────────────
Корзина (3)

┌─────────────────────────────────┐
│ [Фото]  Название товара         │
│         Вариант: 7g             │
│         [ − 2 + ]    300 грн    │
│                            [🗑] │
└─────────────────────────────────┘
┌─────────────────────────────────┐
│ ...ещё товары...                │
└─────────────────────────────────┘

──────────────────────────────────
Итого:                  1 500 грн
[   Оформить заказ   ]            ← Accent кнопка, full-width
```

При нажатии «Оформить заказ» — sheet закрывается, навигация на `/checkout`.

## Страница оформления заказа — подробно

**Файл:** `pages/[region]/[locale]/checkout.vue`

### Данные из src/front

- Список способов доставки: из того же composable/endpoint что в `src/front`
- Список способов оплаты: из того же composable/endpoint что в `src/front`
- Логика формирования заказа: из того же composable что в `src/front`
- Поля формы: соответствуют тем же полям что требует API

### UX деталей формы

**Поле телефона:**  
Маска ввода соответствующая региону (CZ → +420, UA → +380).  
Использовать ту же маску что в `src/front`.

**Адрес (при курьерской доставке):**  
Одно текстовое поле или несколько (улица, дом, квартира).  
Зависит от логики `src/front`.

**Отделение (при доставке в отделение):**  
Поиск по тексту (autocomplete) или выбор из списка.  
Полностью переиспользовать компонент/логику из `src/front`.

### Порядок секций формы

```
1. [Развернуть] Товары в заказе (N штук)
   ↳ список при раскрытии

2. Получатель
   - Имя [инпут]
   - Телефон [инпут с маской]
   - Email [инпут] (если требуется)

3. Доставка
   [○] Вариант 1 — название, описание, цена
   [○] Вариант 2 — ...
   ↳ Поля адреса/отделения (появляются под выбором)

4. Оплата
   [○] Вариант 1
   [○] Вариант 2

5. Комментарий к заказу (textarea, необязательно)

6. Итог
   Товары:    ______ грн
   Доставка:  ______ грн
   ─────────────────────
   Итого:     ______ грн

7. [Оформить заказ]  ← Accent, full-width
```

### Отправка формы

1. Фронт-валидация всех полей
2. Кнопка → disabled + spinner
3. POST на тот же endpoint что `src/front`
4. Успех → `navigateTo('/{region}/{locale}/thank-you')` + `cart.clear()`
5. Ошибка → toast с текстом ошибки, кнопка снова активна

## Страница «Спасибо за заказ» — UX

- Использовать Telegram WebApp API: `WebApp.HapticFeedback.notificationOccurred('success')`
- Если Telegram доступен, показать нативное сообщение: `WebApp.showAlert` — опционально
- Кнопку «Назад» в TopBar — скрыть или сделать так чтобы она вела на главную, а не на `/checkout`
- `navigateTo` на `/thank-you` должен заменять историю: `replace: true`
