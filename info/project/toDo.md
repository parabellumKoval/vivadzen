# High-level To‑Do

1. **Expose the AI content generator to clients.** `src/api/packages/ai-content-generator` only wires Backpack CRUD and settings (routes in `routes/admin.php`); there is no public API to call `ContentGenerator`, so front-end marketing teams cannot leverage the same driver registry/logging. Add a throttled API endpoint (or queue job) that mirrors the admin logging/driver selection before the UI can reuse it.
2. **Align the profile API with the guard/schema contract.** `App/Http/Controllers/Api/ProfileController::update` uses `auth:sanctum` but pulls the user through the `profile` guard (see `packages/profile/src/app/Http/Controllers/Api/ProfileController.php`), and `packages/profile/IMPROVEMENTS.md` lists schema mismatches (e.g., `firstname` vs `first_name`). Decide on a single guard, fix the migration vs. model shape, and add regression tests for profile/wallet endpoints so the API routes (documentation in `packages/profile/src/routes/api`) work in production.
3. **Surface remote dumps in the admin UI.** `packages/dumper` supports remote dump delivery (`RemoteDumpManager` and `BunnyRemoteDumpProvider`) but `DumperController` (`src/.../DumperController.php`) only lists local manual/auto cases. Extend the widget or controller so admins can restore/delete remote backups, inspect status, and trigger retention/cleanup based on `config/dumper.php` retention settings.
4. **Capture more review/reward telemetry.** The referral triggers in `app/Services/Referral/Triggers/*` focus on specific events, but the front-end push (via `webhooks` units like `refresh_homepage_lists`) is hardcoded. Consider tracking translation/schedule updates via existing `webhooks` config or adding dynamic webhook unit registration so new domains (e.g., blog or landing pages) can react without editing PHP.
